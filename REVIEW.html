Verdict

Approve

The fix is minimal, correctly scoped, and matches the described root cause — a permafail on 4.23 nightly jobs caused by the OS-version test defaulting to rhel-10 for jobs with no explicit stream marker in the name. The follow-up commit is a net simplification.

What this PR does

  • Fixes validateStandaloneNodeOS in test/extended/ci/job_names.go so jobs with no explicit rhcos9/rhcos10/-runc marker correctly expect rhel-9 on 4.x clusters instead of unconditionally defaulting to rhel-10.
  • Fixes the specific failure: 4.23 nightlies run RHCOS9 but the test expected RHCOS10 by default, since 4.23 has no explicit stream marker in job names.
  • Since previous review: the author force-pushed a follow-up commit that removes the separate strings.Contains(jobName, "upgrade") branch and merges it with the default-case branch into a single unified else, using getInstallVersion() uniformly instead of parsing Status.Desired.Version separately for the non-upgrade default case.
  • Single file, net 4 insertions / 9 deletions vs. the previously reviewed version — a simplification, not new scope.
