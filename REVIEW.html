OCPBUGS-86225: fix PDB AlwaysAllow test failure on IPv6-primary dualstack clusters

✓ Approve

Minimal, correct fix for a real test flake on IPv6-primary dualstack clusters. The root cause analysis is accurate, both the source YAML and generated bindata.go are updated in sync, and no production code is touched. The only noteworthy item is a cosmetic inconsistency in nginx ipv6only usage relative to a nearby config — not a correctness issue.

What this PR does

  • Fixes the PDB AlwaysAllow e2e test, which deploys nginx pods and waits for them to become Ready via an HTTP readiness probe on port 8080.
  • On IPv6-primary dualstack clusters, the kubelet probes the pod's IPv6 address; the previous nginx config only bound to 0.0.0.0:8080 (IPv4), causing connection refused and pods never becoming Ready.
  • Adds listen [::]:8080; so nginx accepts connections on both IPv4 and IPv6 — standard dual-stack nginx pattern.
  • Updates both the authoritative YAML (nginx-with-delayed-ready-deployment.yaml) and its generated embedding (bindata.go) consistently.

Findings

Nits

nit Inconsistent ipv6only usage compared to nearby nginx config
test/extended/testdata/poddisruptionbudgets/nginx-with-delayed-ready-deployment.yaml:70  /  test/extended/testdata/bindata.go:51172-51173
A sibling nginx config in the same bindata.go (lines 51715–51716) uses the pattern listen [::]:8443 ipv6only=on; alongside listen 8443;. This PR omits ipv6only=on for port 8080. Without it, the IPv6 socket's dual-stack behavior depends on the kernel's net.ipv6.bindv6only setting; on the Linux default (0) the IPv6 socket could be dual-stack, potentially conflicting with the explicit listen 8080; directive. Nginx handles this gracefully in practice and the fix is correct either way, but the inconsistency is worth noting. 
# This PR (port 8080):
listen 8080;
listen [::]:8080;

# Existing config (port 8443, bindata.go:51715):
listen 8443;
listen [::]:8443 ipv6only=on;

Things I checked and was fine with

  • Root cause is accurate: listen 8080; binds IPv4 only; kubelet on IPv6-primary clusters probes via the pod's IPv6 address; connection refused prevents pods reaching Ready state.
  • The dual-directive pattern (listen 8080; listen [::]:8080;) is the standard recommended nginx dual-stack configuration and works correctly.
  • Source YAML and generated bindata.go are updated in sync — no regeneration gap.
  • Zero production code is touched; risk is confined to test fixtures.
  • IPv4-only clusters are unaffected: IPv4 probes still resolve to listen 8080;.
  • No new test for IPv6-primary topology is needed — this fix unblocks the existing test; adding topology-gated infrastructure is out of scope for a flake fix.

Open questions for the author
